# 安装与开发

源码面向 Windows，需 Python3.12、Node.js/npm（支持Vite6的版本）、uv、Git、Chrome、WebView2，以及 PATH 中的 ffmpeg/ffprobe。桌面编译另需 Rust/MSVC、Visual Studio C++ 与 Windows SDK。锁定依赖见 package-lock.json、uv.lock、src-tauri/Cargo.lock。

## 启动后端与网页

在源码根目录 PowerShell 执行：

```powershell
npm ci
uv sync --frozen
npm run build
$env:MOFLOW_DATA = Join-Path $env:LOCALAPPDATA 'MoflowStudio/data'
& ./.venv/Scripts/python.exe service.py --data $env:MOFLOW_DATA
```

打开 http://127.0.0.1:7861 。先构建前端再访问，在设置中将默认D盘素材路径改为实际可用目录。不要同时运行占用同一端口或同一Chrome资料目录的多个服务。

需要热更新时，在另一个 PowerShell 的相同目录执行 `npm run dev`，访问 http://127.0.0.1:5178 ，API由Vite代理到7861，后端保持运行。

密钥在设置中输入，不随仓库提供。Ollama填实际模型名和地址；DeepSeek测试实际可用模型；兼容API按服务商配置地址。源码默认模型名不是长期可用保证。RunningHub自动生产需要独立API密钥与权限，网页登录不等于API授权。

## 测试

```powershell
npm run build
$env:MOFLOW_DATA = Join-Path $env:TEMP 'moflow-tests'
& ./.venv/Scripts/python.exe -m pytest -q
```

部分测试需要Windows和FFmpeg。scripts下accept_*、check_*等属于原机器现场验收脚本，可能调用真实搜索、下载、索引或模型接口，先阅读再运行，不要当无副作用单元测试批量执行。

## 构建桌面

现有构建脚本保留了原开发机的固定布局，**不是通用安装器**。运行前逐项调整：

| 脚本 | 检查项目 |
|---|---|
| scripts/build-service.ps1 | D盘工作/临时目录、FFmpeg PATH、虚拟环境和资源联接目标 |
| scripts/build-desktop.ps1 | Rust/Cargo目录、MSVC路径和SDK/库版本 |
| scripts/package-release.ps1 | 构建输出、交付目录、许可证路径及快捷方式目标 |

确认本机环境后依次执行：

```powershell
npm run build
./scripts/build-service.ps1
./scripts/build-desktop.ps1
./scripts/package-release.ps1
```

先PyInstaller生成服务sidecar及Tauri资源，再编译Rust壳，最后组合便携目录。打包前退出旧程序。仓库没有上传虚拟环境、Rust工具链、FFmpeg二进制或_internal，应自行安装与构建。

原生目录、文件定位、内嵌官网和上传桥接需要桌面实测。干净机器完整构建尚未实测，原开发机通过不等于任意机器可直接安装。DPAPI凭据与浏览器登录不应复制到另一台电脑，应重新填写密钥并登录。
